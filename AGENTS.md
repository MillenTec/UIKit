# AGENTS.md

Kotlin **Compose Multiplatform** library (a Windows/macOS/Android/iOS "UIKit"-style UI kit) plus a gallery sample app. `README.md` (中文) and `README.en.md` at repo root cover the theme system, layered/animatable icons, and acrylic materials — read them before changing library APIs that appear there.

## Working directory gotcha

The Gradle project lives in `src/`, **not the repo root**. Always run Gradle from `D:\Projects\Libraries\UIKit\src` (as `workdir`). Repo root has no build files.

## Modules (`src/settings.gradle.kts`)

- `uikitMain` — the shipped library. Targets `iosArm64`, `iosSimulatorArm64` (static framework `UIKit`), JVM, Android. Maven coords `com.millentec.uikit:uikit`, version `0.0.1-dev`, published via `maven-publish`.
- `sharedExample` — shared gallery app (iOS/JVM/Android targets); the only module that depends on `uikitMain`.
- `androidExample` — Android launcher APK. Its release signing config reads keystore path/passwords from `src/local.properties` (local, never committed; `*.jks` is gitignored).
- `desktopExample` — desktop launcher. Run the app with `:desktopExample:run` (mainClass `com.millentec.compose.uikit.MainKt`).
- `iosApp/` — plain Xcode wrapper project (not a Gradle module), standard CMP template.

## Common commands

From `src/`:

```sh
./gradlew :desktopExample:run        # run the gallery on desktop
./gradlew :uikitMain:publishToMavenLocal
./gradlew :uikitMain:compileKotlinJvm  # fast sanity compile of the library
```

There is **no test suite (commonTest is empty), no CI, no README, no lint config**. Verification = compilation + running the desktop app. Don't invent `test`/`lint` expectations.

## Icons (likely edit target)

Icon set under `uikitMain/.../icons/fluenticons/`, in `regular/dp20/` and `filled/dp20/` (plus `animatable/` and `resizeable/`). Every icon file is an `ImageVector`-builder extension on `FluentIcons` / `FluentIcons.Filled` with a private `_Name` cache and a hardcoded brand color; keep that exact pattern when adding icons.

**Codegen trap:** `sharedExample/.../IconGalleryList.g.kt` (the `.g.kt` suffix marks generated files) is committed and regenerated by the Kotlin script `sharedExample/src/tools/IconCollector.kts`, which scans only `regular/dp20` and `filled/dp20` and decides between a function call (`fun FluentIcons.` present in the file) or a bare property reference. After adding a dp20 icon, regenerate it with the Kotlin CLI from `src/sharedExample/src/tools`:

```sh
kotlin IconCollector.kts
```

## Library conventions

- Theme values come from composables `getUIKitTheme()`, `getUIKitColors()`, `getUIKitShapes()`, `getUIKitTypography()`, etc. in `uikitMain/.../theme/ThemeGetter.kt` (all read `UIKitTheme.LocalTheme.current`) — **not** `MaterialTheme`. Follow this in library components.
- `expect fun getScreenCornerRadius()` / `getOperatingSystem()` (`Platform.uikit.kt`) have actuals under `uikitMain/src/{androidMain,jvmMain,iosMain}`; sharedExample has its own `Platform.kt`.

## Environment / build quirks

- Local JDK 21 is expected (README quickstart; Gradle wrapper is 9.5).
- Dependency resolution and the Gradle wrapper distribution URL point at **Aliyun mirrors** (`settings.gradle.kts`, `gradle-wrapper.properties`); no network/mirror access breaks builds.
- Gradle configuration cache is enabled; `org.gradle.jvmargs=-Xmx4096M`, `kotlin.daemon.jvmargs=-Xmx3072M`.
- Kotlin 2.4.0, AGP 9.1.0, Compose Multiplatform 1.11.1, JVM target 11, Gradle 9.5.
